# Sports engine (NFL)

`nfl_engine` is a play-by-play Monte Carlo football simulator that is **trained on completed
games** and **backtested on games it never saw**. It consumes team, quarterback, coach, opponent,
weather, venue and rest data and returns full score distributions for real upcoming games.

```bash
python -m nfl_engine train                 # learn, calibrate, backtest -> docs/SPORTS_BACKTEST.md
python -m nfl_engine upcoming              # simulate the next slate, flag games worth a look
python -m nfl_engine predict KC BUF        # one unplayed matchup from the schedule
```

Data is free and public (nflverse play-by-play + schedule/lines/weather) and cached in `data/sports/`.

## What the simulator models

Each simulated game steps through snaps: play-call → pre-snap penalties → sack / scramble /
completion / incompletion / interception / run / lost fumble → yardage → down & distance → clock burn;
fourth-down decisions (go / punt / FG), field goals with distance + weather, punts, kickoffs by rule era,
PAT vs. two-point chart, onside tries, two-minute drill & milk-the-clock behaviour, kneel-downs,
halftime, return touchdowns and overtime.

| Layer | What it learns | Source |
|---|---|---|
| League model (`league.py`) | play-call model, 4th-down policy, yardage pools by field position & distance (with end-zone censoring), clock pools, penalties, kicking, weather sensitivities | ~500k plays |
| Team ratings (`ratings.py`) | opponent-adjusted, decayed, shrunk offence **and** defence ratings: sacks, scrambles, completion, INT, yards/completion, yards/carry, fumbles, penalties, pace, pass-rate-over-expected, FG skill | play-by-play |
| Player layer | starting-QB ratings (separate from his supporting cast), per-QB sample size | games + play-by-play |
| Coach layer | 4th-down aggressiveness by head coach | play-by-play |
| Context (`matchup.py`) | wind / cold / dome, home field, neutral site, playoff vs. regular season, kickoff rule era | schedule |
| Calibration (`pipeline.py`) | solves home-field and scoring-level levers so simulated league margin / total match real; trust scale for ratings | completed games |
| Team residuals (`residual.py`) | persistent per-team scoring gap the play model misses (special teams, explosiveness, finishing drives) | completed games |

Ratings are computed by walking the schedule chronologically and snapshotting what was known **before**
each kickoff, so backtests contain no look-ahead.

## Sports engine tab (web app)

Start the desk as usual and open **Sports engine**:

* **Live: engine vs actual** - every in-progress/finished game on the ESPN scoreboard. For each snap the
  engine's *pre-snap* prediction (pass probability, expected yards with 10th-90th percentile range,
  first-down/TD probability, 4th-down go/punt/FG odds) sits next to what actually happened, with a
  yardage percentile and a surprise score. A whole-game table compares predicted and actual pass rate,
  yards/play, conversion, completion, sack and turnover rates, and the engine's live win probability is
  shown next to ESPN's. Calibration check: ~10% of plays should land below the engine's 10th and above its
  90th percentile.
* **Slate** - simulated upcoming games vs the market.
* **Player matchups** - per-player stat lines from the same simulation (targets by share, receiver and rusher
  skill relative to their own team, defenders credited with sacks/PBUs/INTs by share, roster + injury report
  filters). Spotlight a receiver at a chosen target share and optionally shadow him with a defender to
  compare baseline vs matchup.
* **Nightly tuning** - status, run hour, current live corrections, run history.

Nightly job (`livetune.py`): once per night at the configured local hour (default `0` = midnight, set with
`SPORTS_TUNE_HOUR` or in the tab) **and only after every game on the scoreboard is final**, it (1) folds all
graded live plays into small shrunk, bounded corrections (pass rate, completion, sack, interception, yards
per completion/rush) used by every later simulation and live prediction, (2) re-downloads results and
updates ratings and the team-residual book, and (3) saves the model. The first run needs >=30 graded plays.

API: `/api/sports/{status,live,live/{event},slate,roster/{team},h2h,tune}`.

## Validation

`docs/SPORTS_BACKTEST.md` is regenerated by `train` and compares, on seasons after `--train-end`:
winner accuracy, Brier / log loss, margin & total error, probability calibration, box-score realism and
the closing market. Read it before trusting any output — the closing line is the benchmark to beat.

## Using the output

`upcoming` writes `data/sports/upcoming.csv` (and optional markdown with `--out`): projected score, win
probability, model vs. market spread/total, cover/over probabilities and flags (spread lean, total lean,
upset watch, coin-flip, shootout/grinder, thin QB sample). Treat flags as a shortlist to investigate, not
as bets; check injuries and late news that the engine cannot see.

## Known limits

* Injured/inactive players are removed from player lines (injury report + roster status), but team ratings
  do not yet re-weight for a missing non-QB starter, and depth charts / in-game momentum are not modelled; starting QBs are taken from the
  schedule file (`games.csv`), so a late scratch is invisible until the file updates.
* Team ratings use unit-level outcomes; individual players are modelled for who gets targets/carries and
  for sack/PBU/INT share only (public data has no coverage assignments or blocking), so player-vs-player
  defender effects are directional.
* Playbook/scheme is represented through pass-rate-over-expected, pace and 4th-down tendencies, not
  formations or concepts.
* NFL outcomes are noisy: even the closing market misses by ~10 points on average.

## Unabated market board

The Slate sub-tab also shows live sportsbook lines from [Unabated](https://docs.unabated.com): consensus spread/total
next to the engine's, plus the best moneyline price per side. Configure in `.streamlit/secrets.toml` (never commit it) or the environment:

```toml
UNABATED_API_KEY = "..."        # server-side only, sent in the X-Api-Key header
UNABATED_PARTNER_CODE = "..."   # the code on tools.unabated.com/api-keys
```

API rules followed: one odds request per 5 s (30 s cache, `Retry-After` honoured); deep links are Unabated's own
`deepLink` values with only `utm_campaign` set to the partner code (existing value replaced, path untouched);
no links are shown until a partner code is set; the key never appears in a page or link.
